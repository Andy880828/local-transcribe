## 待補完

- **講者分辨準確度沒有量測**：只驗證過「分得出多位講者」，沒有標註真值可算 DER。
- **講者只標到「段落」層級**：Whisper 把問與答切在同一段時，講者分辨無法在段內切開
  （`samples/白色檔案/全文.MOV` 實測：問答全被標成同一人）。whisperx 對齊後其實有逐字講者，但目前輸出時丟棄。
  重評條件：使用者確認該片段確實是兩個人在說話 → 改為依逐字講者變化切段。
- **meeting-summary SKILL 只有格式規範**：沒有自動化檢查摘要品質（本質上需人工判讀）。
- **大量短檔批次效能**：每檔重新載入模型，未量測；批次 > 20 個檔且平均 < 2 分鐘時重評「模型常駐」。

## 可能的方向（尚未承諾）

近期：
- `transcript merge`：同一場會議分段錄音的逐字稿合併（時間軸位移）。
- 講者辨識跨檔一致（同一人在不同檔案都叫 SPEAKER_00 的不同人）——需要 speaker embedding 比對。

較遠：
- 熱詞／專有名詞表提示（降低中文同音誤辨），視 WhisperX 支援程度。

## 明確不做

| 項目 | 理由 |
|---|---|
| 獨立 `batch` 指令 | 已併入 `run`（多檔／資料夾），避免旗標重複宣告 |
| CLI 內建 LLM 摘要 | 由 agent 依 SKILL 撰寫，不在工具內放 API 金鑰 |
| `doctor` 環境檢查指令 | 使用者本輪未選；`run --dry-run` 已涵蓋輸入與 token 檢查 |
